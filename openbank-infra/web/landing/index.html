Bank as Code

The bank explains itself.

A running service exposes its own API contract, version and health. Its documentation travels with its release, so teams can inspect what is deployed and trace it back to the code.

See docs-as-service in the source →
01 / SERVICESelf-describing services

Live endpoints report the deployed version, API contract and health.

02 / DOCUMENTATIONDocumentation as Code

Service-owned docs ship with the release; generated decisions and runbooks are checked for drift.

03 / GOVERNANCECompliance as Code

Each service declares ownership, lineage and retention. CI cross-checks claims that the code can verify.

04 / EVIDENCEReady to examine

Link a change to its contract, tests and operational signals, giving reviewers a path from a claim to its evidence.

The public catalog is a code-derived snapshot, not a live deployment report. Running-service endpoints and operational views show current state.
